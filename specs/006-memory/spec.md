## 1. 背景与定位

Provider 让 Agent 会调模型，ReAct 让它会思考，Tool 让它会动手，Notify 让它会主动开口。但它还缺一样东西：**记性**。

大模型每次调用都是无状态的，Agent 要靠调用方把历史塞进上下文。Demo 能跑，是因为整段对话塞得进一个上下文窗口；生产会崩，是因为真实用户会跨会话、跨天、跨话题地回来。本特性补的就是这个缺口——**在有限的上下文窗口之外，给 Agent 一套记得住事的机制**。

按宪法原则 V，Memory 必须做成**统一门面**：引擎只调抽象的"回忆/记住"，至于背后是文件、关系库还是别的，引擎不感知。这样后续升级存储（扩展阶段的向量检索）时上层一行不用改——这是平滑长大的技术前提。

**边界声明**：

- 核心阶段采用**文件式长期记忆 + 关键词检索**，零外部依赖，契合单二进制、私有部署定位。
- 长期记忆分**核心记忆**（始终在场、不检索、不截断）与**归档记忆**（可检索、可截断）两个区块；写入由 Agent 通过工具显式决定，**不做系统自动提炼**。
- **不**交付：语义/向量检索、情景记忆、自动提炼与记忆压缩、记忆的按 Agent/用户隔离、记忆查询接口（CLI/Web 端点）、上下文压力触发的自动整理。这些全部属扩展阶段。
- 本特性**不**新增 Maven 模块。
- 会话记忆（当前对话历史）**已经存在**，由 Session/SessionManager 负责；本特性只负责长期记忆，以及把两者统一到一个门面之后对外暴露。

## 2. 现状与本次要补的缺口

记忆相关的**骨架类已经写好但全未接线**，运行时的长期记忆链路实际是断的。真正缺的是把这一串接起来、把结构改对、把测试补上：

| 缺口 | 当前表现 |
|---|---|
| 统一门面没有实现 | 门面接口定义了三个方法，但**全仓库没有任何实现类**；依赖它的读适配器与两个工具都拿不到实例 |
| 三个类全未装配 | 文件读写类、读适配器、两个工具**没有任何 Spring 装配点**（无配置类、无构造调用），运行时注入到引擎的读端口恒为 `null` |
| 长期记忆实际是空的 | 因为读端口为 `null`，组装 Prompt 时"长期记忆"这一段**恒返回空串**——Agent 现在完全不记得任何事 |
| 记忆文件路径自相矛盾 | 工作区初始化在工作区**根目录**建 `MEMORY.md`，而文件读写类操作**子目录** `memory/MEMORY.md`；两个位置各有一个文件 |
| 记忆没有分区概念 | 读写类只有"追加/读全文/关键词检索"，没有核心与归档的区分，写入工具也没有让 Agent 说明写哪一类的参数 |
| 截断会把核心内容一起裁掉 | 现有截断逻辑对**整个文件**从头截断，一旦触发，本该"永远在场"的核心内容会被一起删掉 |
| 记忆工具对 Agent 不可见 | 两个工具没被注册进工具注册表，Agent 根本看不到它们，即使调也调不动 |
| 没有任何测试 | 该模块无测试目录；模块也未引入配置与测试所需依赖 |

## 3. User Scenarios & Testing *(mandatory)*

### User Story 1 - Agent 能把值得记住的事记下来、并在需要时想起来 (Priority: P1)

用户在对话里说了一句值得长期记住的话（偏好、项目事实、结论）。Agent 自己判断"这句该记"，调用记忆写入工具把它记下来；下次遇到相关问题时，先用检索工具查一下自己是否已经知道，避免重复记录。

**Why this priority**: 这是整节的地基。没有它，Agent 依旧每次对话都从零开始，前面几节交付的能力全部停留在"单次对话"级别。有了它，才谈得上"跨会话记得住谁是谁"。

**Independent Test**: 不依赖模型、不依赖外网。直接用真实的临时工作区调用两个工具：断言写入后**立刻**可被读出（同一进程内、无缓存、无需重启），断言检索命中、未命中不报错，断言分类参数把内容落到正确的区块。

**Acceptance Scenarios**:

1. **Given** 一个空的工作区，**When** 调用记忆写入工具写入一条内容，**Then** 该内容出现在记忆文件里，并带上日期。
2. **Given** 刚写入一条内容，**When** 同一进程内立即构建一次上下文，**Then** 该内容立刻可见（不依赖缓存刷新、不依赖重启）。
3. **Given** 记忆里已有"用户偏好用中文回答"，**When** 用关键词检索，**Then** 返回包含该内容的条目。
4. **Given** 记忆里没有任何相关内容，**When** 用关键词检索，**Then** 返回明确的"没有找到相关记忆"提示，**而不是抛异常或中断对话**。
5. **Given** 记忆文件的父目录不存在，**When** 调用写入工具，**Then** 目录被自动创建，写入成功。
6. **Given** 记忆文件不存在（全新工作区），**When** 构建一次上下文，**Then** 返回空内容，**不报错**。
7. **Given** 写入工具的调用参数无法识别（分类取值非法），**When** 调用，**Then** 返回失败结果并说明合法取值，**不得静默写入错误区块**。
8. **Given** Agent 调用了记忆工具，**When** 查看工具调用审计，**Then** 该调用与其他工具一样被记录（与既有审计链路一致）。

---

### User Story 2 - 每次新对话都自带长期记忆 (Priority: P1)

用户重启应用、开一个全新会话，问一个和上次有关的问题。Agent 不需要用户重新解释——它组装上下文时就自动带上了长期记忆内容，直接沿用上次记下的偏好与事实。

**Why this priority**: 这是 Demo 二（跨对话记偏好）能成立的关键一环。写入能力（US1）只是把事存下来，只有注入了才真正"用得上"。

**Independent Test**: 不依赖模型。构造一份带内容的记忆文件，断言构建出的系统提示词里包含长期记忆内容，且**恰好只出现一次**（不与对话历史重复注入）；再断言记忆为空时该段为空串、不影响提示词其余部分。

**Acceptance Scenarios**:

1. **Given** 记忆文件里有若干条归档记忆，**When** 组装一次 Prompt，**Then** 系统提示词的"长期记忆"段包含这些内容。
2. **Given** 同一份记忆内容，**When** 组装 Prompt，**Then** 该内容**只出现在长期记忆段**，不与对话历史段重复。
3. **Given** 记忆为空，**When** 组装 Prompt，**Then** 长期记忆段为空串，提示词的其余部分（身份、Bootstrap、对话历史、工具清单）不受影响。
4. **Given** 应用重启（新进程，记忆文件不变），**When** 组装 Prompt，**Then** 长期记忆内容依然在（文件天然跨重启）。
5. **Given** 引擎侧只依赖统一门面，**When** 检查调用链，**Then** 引擎不直接读写记忆文件、不直接访问会话存储（符合宪法原则 V）。

---

### User Story 3 - 核心记忆永远在场，不会被截断吃掉 (Priority: P2)

用户身份、项目背景、关键约束这类信息，Agent 把它们写进"核心记忆"。无论归档记忆积累多少、无论截断触发多少次，这些核心内容必须一字不少地出现在每次对话里。

**Why this priority**: 它解决的是"Agent 每次对话都记得你是谁"这个最影响体感的需求，实现成本极低；但它建立在 US1/US2 之上，所以排 P2。同时它是第 22 节点名的**最容易被后来者"优化"掉的坑**，必须有回归测试钉死。

**Independent Test**: 不依赖模型。先写核心记忆，再把归档区灌到远超阈值，断言加载结果里核心内容完整、归档区只保留最近内容；并断言核心区不参与检索、不参与截断。

**Acceptance Scenarios**:

1. **Given** 写完一条核心记忆，**When** 加载记忆，**Then** 核心内容完整出现。
2. **Given** 核心记忆若干条 + 归档记忆远超阈值，**When** 加载记忆，**Then** 核心内容**一条不少**，归档区**只保留最近的部分**、最早的部分被丢弃。
3. **Given** 归档区超阈值触发截断，**When** 检查核心区文本，**Then** 字节级未发生变化。
4. **Given** Agent 写入时未指定分类，**When** 调用写入工具，**Then** 内容落到归档区（安全默认）。
5. **Given** Agent 指定分类为核心，**When** 调用写入工具，**Then** 内容落到核心区，且后续检索**不返回**它（核心记忆本来就永远在场，无需检索）。
6. **Given** 同一个 Agent 在两次不同分类下写入，**When** 查看记忆文件，**Then** 文件由两个区块组成，内容各归其位，读全文时按区块返回。

---

### User Story 4 - 工作区初始化把记忆文件放到规范位置 (Priority: P3)

开发者执行工作区初始化命令。记忆文件应该被创建在**规范路径**下，并且如果他此前误在旧位置放过一份记忆内容，这份内容不应该丢。

**Why this priority**: 它不影响 Agent 的记忆能力本身，但当前"两个位置各有一个文件"的状态会让人分不清哪个才是真的。排 P3 是因为它独立、可后置，不阻塞前三个故事。

**Independent Test**: 不依赖模型。在临时目录跑初始化：断言规范路径下的记忆文件存在且带两个区块；断言旧位置不再新建；再针对"旧位置已有内容"的场景断言内容被迁移、且不覆盖已有的新内容。

**Acceptance Scenarios**:

1. **Given** 一个全新的空目录，**When** 执行工作区初始化，**Then** 规范路径（`memory/MEMORY.md`）下的记忆文件被创建，且带两个区块标题。
2. **Given** 全新空目录，**When** 执行初始化，**Then** 工作区**根目录不再生成** `MEMORY.md`。
3. **Given** 旧位置（工作区根）存在一份**有内容**的旧记忆文件、规范路径下尚无内容，**When** 执行初始化，**Then** 旧内容被迁移到规范路径，且旧文件被保留为备份以便回溯。
4. **Given** 规范路径下**已有非空**记忆内容，**When** 执行初始化，**Then** 不覆盖、不合并，直接跳过迁移并给出可诊断提示。
5. **Given** 初始化重复执行多次，**When** 查看记忆文件，**Then** 内容不被重复写入或清空（幂等）。

---

### Edge Cases

- **记忆文件内容被手工改坏**（缺区块标题、区块顺序颠倒、多出一段自由文本）→ 系统必须按"取不到就当空"处理，绝不因为格式问题让对话中断。
- **记忆条目内容里含换行或 Markdown 标题符号**（Agent 写入多行文本）→ 写入后仍必须能被检索到、且不污染区块结构（不能因为写入内容里有 `## ` 就切出第三个区块）。
- **归档区刚写入就把自己截掉**（单条内容超过阈值本身）→ 必须保证"至少保留最近写入的那一条"，不能出现写完就查不到的自我矛盾。
- **同一进程内多个会话并发写入** → 不允许出现内容丢失或文件写坏（截断/覆盖导致半条记录）。
- **记忆文件路径指向目录**（误配置）→ 返回失败结果而非抛出未捕获异常。
- **Agent 用大小写不同的关键词检索**（`Memory` / `memory`）→ 视为同一个关键词。
- **超长关键词/空关键词检索** → 空关键词不得返回全量（不能变成"读出整个归档区"的旁路）。

## 4. 澄清结论（开工前拍板）

本特性与既有文档存在 4 处冲突，已与用户确认，结论如下（`/speckit.plan` 必须按此执行）：

| 编号 | 冲突点 | 结论 |
|---|---|---|
| C-001 | 统一门面归属哪个模块 | **接口上移到 core**（端口在 core、实现在 memory 模块），符合既有惯例（会话存储端口同样在 core）；引擎侧直接依赖该门面，既有的读适配器端口退役 |
| C-002 | 注入内容是否含会话历史 | **只注入长期记忆**；会话历史仍由提示词的独立一段负责，禁止重复注入 |
| C-003 | 是否采纳"核心/归档两区块 + 写入分类参数" | **采纳**，并同步更新 `docs/TechnicalSolution.md` §5.2 与 `website/docs/memory.md`、`website/zh/docs/memory.md`，消除文档冲突（该处旧文档描述为"单列表、不分区"） |
| C-004 | 记忆文件路径不一致 | **改初始化命令**：在规范路径创建；根目录旧文件若**有内容**则**迁移一次**并保留备份 |

## 5. Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Agent 必须能通过两个内置工具与长期记忆交互：一个写入、一个按关键词检索；两者必须与其它内置工具一样出现在可调用工具清单中，并受既有的 Agent 工具授权过滤约束。
- **FR-002**: 写入工具必须接受"内容"与可选的"分类"两个参数；分类取值为核心或归档，**缺省为归档**；取值大小写不敏感；无法识别的取值必须返回失败结果并告知合法取值。
- **FR-003**: 长期记忆必须存放在规范路径 `<工作区>/memory/MEMORY.md`；文件不存在时按"空记忆"处理，写入时自动创建父目录与文件。
- **FR-004**: 记忆文件必须由两个区块构成——核心记忆与归档记忆；读全文时按"核心区在前、归档区在后"返回；写入时按分类路由到对应区块。
- **FR-005**: 每次构建上下文时必须**重新读取**记忆文件，不得缓存；写入后同一进程内的下一次构建立即可见。
- **FR-006**: 归档区内容超过阈值（4000 字符）时必须截断，**只保留最近的内容**；核心区**永不参与截断**。
- **FR-007**: 无论何种情况，截断后核心区内容必须与截断前**完全一致**（逐字节）。
- **FR-008**: 关键词检索必须**只作用于归档区**，匹配大小写不敏感；命中返回匹配条目，未命中返回明确的"没有找到相关记忆"文本；**不得抛异常**；空关键词必须直接返回未命中，不得返回全量。
- **FR-009**: 注入到 Prompt 的长期记忆内容必须为"核心区完整 + 归档区（必要时截断）"，且**只注入一次**，不与对话历史重复。
- **FR-010**: 记忆为空（文件缺失、区块缺失、区块为空）时，注入内容为空串，**不得**产生空标题或让提示词其余部分受损。
- **FR-011**: 引擎（ReAct 循环与提示词组装）必须**只通过统一门面**访问记忆；不得直接读写记忆文件或直接访问会话存储（宪法原则 V）。
- **FR-012**: 记忆只追加、不删除；唯一的"遗忘"机制是归档区截断，且该机制不得作用于核心区。
- **FR-013**: 记忆写入必须并发安全：同一进程内多个会话并发写入时，不丢内容、不出现半条记录。
- **FR-014**: 记忆写入内容即使包含换行或 Markdown 标题符号，也不得破坏两区块结构，且仍可被检索命中。
- **FR-015**: `USER.md` 必须保持**只读**：本特性不得引入任何写 `USER.md` 的代码路径。
- **FR-016**: 工作区初始化必须创建/初始化规范路径下的记忆文件（含两个区块标题），不再在工作区根创建 `MEMORY.md`；初始化必须幂等。
- **FR-017**: 若工作区根存在**有内容**的旧记忆文件且规范路径下尚无内容，初始化必须把旧内容迁移到规范路径，并保留旧文件为备份；若规范路径已有非空内容，必须跳过迁移并给出提示。
- **FR-018**: 记忆工具调用必须走既有工具执行链路，并落既有审计表（与其它工具一致）。
- **FR-019**: 本特性**不得**引入向量/语义检索、情景记忆、自动提炼与记忆压缩、记忆的按 Agent/用户隔离、记忆查询接口、上下文压力触发的自动整理。

### Key Entities *(include if feature involves data)*

- **长期记忆文件**：规范路径下的一个只追加 Markdown 文件，由两个区块（核心记忆 / 归档记忆）构成，是长期记忆的唯一真身。
- **记忆条目**：一行文本，带日期前缀；归属某个区块；跨越进程重启而存在。
- **记忆分类**：核心 / 归档两种取值，决定条目归属与是否参与截断与检索。
- **记忆门面**：引擎访问记忆的唯一入口，向上提供"取回用于组装的记忆内容"与"记住一条"两类操作；对上层屏蔽存储实现。
- **记忆工具**：写入工具与检索工具两个内置工具，是 Agent 与长期记忆交互的唯二通道。
- **工作区**：记忆文件的根，由全局工作区配置决定；本特性要求初始化命令在此创建规范路径。
- **会话**（既有实体）：承载会话记忆；本特性不改其结构，只在新门面中保持"会话记忆与会话存储解耦"。

## 6. Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户在一次对话里说出的偏好，在**新会话、且进程重启之后**的对话中依然被 Agent 沿用，无需用户重述（Demo 二验收标准，人工走查 1 次通过）。
- **SC-002**: 归档记忆被灌到远超阈值后，核心记忆条目**丢失率为 0**（回归测试断言）。
- **SC-003**: 写入后无需重启、无需刷新，下一次构建上下文**立即可见**（同一进程内即可观察到，延迟为 0）。
- **SC-004**: 检索未命中与记忆文件缺失这两种常见情况，产生**0 次对话中断或未捕获异常**。
- **SC-005**: 记忆为空的全新工作区，对话链路功能**不受任何影响**（与无记忆特性时的行为一致，0 报错）。
- **SC-006**: 本特性交付后，仓库既有测试**全部保持通过**（回归失败数 0）。

## 7. Assumptions

- **A-001**: 长期记忆**按工作区共享**，不按 Agent/用户隔离（按 Agent 隔离明确属扩展阶段，见 `website/docs/memory.md` 规划章节）。
- **A-002**: 关键词检索是**单关键词的包含匹配**，不分词、不正则、不排序打分；语义检索属扩展阶段。
- **A-003**: 4000 字符阈值为常量，本特性**不做成配置项**（避免为未验证的需求先加配置面）。
- **A-004**: 会话历史继续由既有的提示词段落负责，本特性不改变其截断与拼装方式。
- **A-005**: 记忆写入**不需要模型参与**（不做自动提炼）；是否"值得记"由 Agent 在对话中自己判断。
- **A-006**: 当前工作目录**不是 git 仓库**，因此 Spec-Kit 的分支/提交钩子不适用；开发完成后由用户自行决定是否纳入版本管理。
- **A-007**: 记忆内容默认**明文可读**、允许用户手工编辑（这是文件式方案的核心优势，手工改坏按 Edge Case 处理）。
