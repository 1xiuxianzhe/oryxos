# Contract: MEMORY.md 文件格式与初始化迁移

**契约对象**：`<workspace>/memory/MEMORY.md` 的文本格式，以及 `oryxos init` 对该文件与旧位置遗留文件的处理。
**常量归属**：`io.oryxos.memory.MemoryFiles`（运行时与初始化**共用同一份常量**，禁止两处各写一遍）。

## 1. 路径

| 项 | 值 |
|---|---|
| 目录 | `<workspace>/memory/` |
| 文件 | `<workspace>/memory/MEMORY.md` |
| workspace 来源 | 全局属性 `oryxos.workspace`，默认 `${user.dir}/.oryxos`（与 `ContextLoader`、`McpServerConfigLoader` 一致） |
| 旧位置（仅用于迁移识别） | `<workspace>/MEMORY.md` |

## 2. 骨架与区块

```markdown
# OryxOS Memory

## 核心记忆

## 归档记忆
```

| 常量 | 值 |
|---|---|
| 标题行 | `# OryxOS Memory` |
| 核心区标题 | `## 核心记忆` |
| 归档区标题 | `## 归档记忆` |

**解析规则**（容错优先，任何异常都不许让对话中断）：

| 情况 | 行为 |
|---|---|
| 文件不存在 | 视为空记忆 |
| 两个区块都在 | 分别提取 |
| 只有一个区块 | 另一个视为空 |
| 完全没有区块标题 | 有内容 → 全部内容按"无区块"处理（不注入核心区；注入时原样放在长期记忆段） |
| 区块顺序颠倒 | 按标题定位，与顺序无关（I-05） |
| 区块标题重复出现 | 以**第一个**为准，后续同标题内容归入前一个区块（并把重复标题行计入上一个区块） |
| 额外自由文本（在区块之外） | 忽略，不注入 |
| 读取 IO 失败 / 路径是目录 | 空记忆 + WARN |

## 3. 条目格式

```markdown
- [2026-10-16] 用户叫小王，性能敏感场景偏好用 Java
```

**多行内容**：首行带 `- [日期] ` 前缀，后续行以**两个空格缩进**续行：

```markdown
- [2026-10-16] 第一行
  第二行（缩进续行，不会被当成新条目或新区块）
```

**写入规则**：

| # | 规则 |
|---|---|
| W-1 | 父目录不存在时自动创建（含 `memory/` 目录） |
| W-2 | 文件不存在时先写骨架，再插入条目 |
| W-3 | 目标区块缺失时在文件末尾补齐该区块标题，再插入条目（不重排已有内容） |
| W-4 | 条目插入到目标区块的**末尾**（该区块之后第一个 `## ` 行之前，或文件末尾） |
| W-5 | 内容里的 `#`/`## ` 出现在行首时，因缩进而不构成新标题（I-04） |
| W-6 | 写入是"读-改-写" + 追加的混合操作，必须串行化（单实例锁） |
| W-7 | 只追加，不删除、不改写既有条目（除一次性迁移外） |

## 4. 截断（只作用于注入内容）

| # | 规则 |
|---|---|
| T-1 | 归档区渲染结果超过 4000 字符（`MAX_ARCHIVE_CHARS`）时，只保留**末尾** 4000 字符 |
| T-2 | 截断只发生在**读取/渲染**路径，**不写回磁盘** |
| T-3 | 核心区永不参与截断（逐字节完整，FR-007） |
| T-4 | 单条归档内容本身超过阈值时，至少保证最后写入的这条能被看见（截取末尾即天然满足） |

## 5. 初始化契约（`oryxos init`）

| # | 要求 |
|---|---|
| I-1 | 在规范路径创建记忆文件（骨架），**缺失才创建**；重复执行不覆盖、不清空（幂等） |
| I-2 | 工作区根目录**不再创建** `MEMORY.md` |
| I-3 | `memory/` 目录仍在初始化时创建 |
| I-4 | 其余初始化行为（`profiles/`、`sessions/`、`skills/`、`logs/`、`tools/`、Bootstrap 三件套、`mcp_servers.yaml`、默认 Profile）保持不变 |

## 6. 遗留迁移契约

判定依据：**有效内容** = 忽略空行与以 `#` 开头的行后仍有非空行。

| 场景 | 行为 | 返回值 |
|---|---|---|
| 根目录无 `MEMORY.md` | 无操作（**不创建**任何文件） | `NO_LEGACY` |
| 有遗留文件、无有效内容 | 无操作；遗留文件**原样保留**；INFO 提示 | `NOTHING_TO_MIGRATE` |
| 有遗留文件、有有效内容，规范文件为空或不存在 | 逐条有效行作为**归档**条目写入规范文件（带当天日期）；遗留文件改名为 `MEMORY.md.bak`（同名已存在则加 `-yyyyMMddHHmmss` 后缀） | `MIGRATED` |
| 有遗留文件、有有效内容，规范文件已有非空内容 | **不迁移、不合并**；WARN 提示人工处理；遗留文件保留 | `SKIPPED_TARGET_NOT_EMPTY` |

> **职责划分**：创建骨架文件是 `initialize` 的职责（初始化流程先行调用），迁移函数只做"搬内容 + 备份旧文件"，**不越权创建文件**。因此前两种场景下规范文件可能仍不存在——这是刻意的，避免"调用了一个叫 migrate 的函数，却凭空多了个文件"。

**幂等性**：四种场景重复执行结果一致。迁移**不**触碰 `USER.md`、`AGENTS.md`、`SOUL.md`。
