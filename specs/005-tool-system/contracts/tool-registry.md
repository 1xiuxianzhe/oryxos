# Contract: 工具注册表

**Feature**: `005-tool-system`

## 1. 定位

注册表是"当前到底有哪些工具"的**唯一真相来源**。工具清单的两个查询入口、Agent 组装可用工具，
都必须以它为准，不得各自维护第二份清单或缓存副本。

## 2. 行为契约

| 行为 | 契约 |
|---|---|
| 注册 | 名字未被占用 → 登记成功；**名字已占用 → 拒绝登记并输出告警**（先注册者胜出） |
| 按名取用 | 不存在返回空（不抛异常），由调用方决定如何失败 |
| 全量列举 | 返回当前全部工具，顺序不作保证 |
| 存在性判断 | 返回该名字是否已登记 |

**重名拒绝的理由**：静默覆盖会让"某个来源把另一个来源顶掉"无声发生，
排查时表现为"工具明明注册了却调不到"。告警必须包含被拒绝的工具名与来源线索。

## 3. 注册顺序契约

```text
1. 内置工具（按确定性顺序）
2. 外部服务工具（逐服务、逐工具）
```

**推论**：外部服务与内置工具撞名时，**内置工具胜出**，外部工具被拒绝并告警。
这是刻意选择——内置能力是地基，不应被外部依赖顶掉。

## 4. 不变式

- 注册表中 **不存在** 两个同名工具。
- 注册表中 **每个** 工具的名字、描述、参数 schema 均非空（缺一即视为缺陷）。
- 清单入口返回的集合与注册表内容**恒等**。

## 5. Required Verification

| # | 要求 | 验证方式 |
|---|---|---|
| 1 | 启动后注册表恰好含 7 个工具（6 个本次接入 + 既有 `notify`） | 装配测试：断言名字集合 |
| 2 | 每个已注册工具的名字/描述/schema 非空 | 契约测试：**参数化遍历注册表**，新工具自动纳入 |
| 3 | 重名注册被拒绝且告警，先注册者保留 | 单测：先注册 A，再注册同名 B，断言取到的是 A |
| 4 | 内置工具与外部工具撞名时内置胜出 | 单测：构造撞名的外部工具，断言其未登记 |
| 5 | 存在性判断对已登记/未登记分别返回真/假 | 单测 |
| 6 | 两个清单入口与注册表内容一致 | 单测：受控注册表下断言集合相等 |
