# Contract: 工具授权（按 Agent 过滤）

**Feature**: `005-tool-system`

## 1. 语义

Agent 配置中可声明"这个 Agent 允许使用哪些工具"。运行到该 Agent 时，
组装给模型的工具清单**恰好等于**授权集合——多一个（授权过宽）和少一个（授权过窄）都不算达标。

## 2. 判据与结构

**判据是工具名**。声明沿用既有的对象列表结构，其中只有名字参与过滤：

```yaml
tools:
  - name: read_file
  - name: shell
```

- `description` / `parameters` 当前**不参与**过滤，保留为后续"内联工具定义"的扩展点。
- 兼容增强：**容忍**纯字符串写法（`tools: [read_file, shell]`）。
  若两种形式在解析层无法共存，以对象形式为准并在文档中写明（plan D-05）。

## 3. 语义表

| 声明状态 | 暴露给模型的工具集合 |
|---|---|
| 字段缺失，或声明为空列表 | **不限制** = 注册表全部（A-004，已确认） |
| 声明了 N 个名字 | **恰好**这 N 个 |
| 声明中含注册表里不存在的名字 | 给出**可诊断提示**，指明是哪个名字；不得静默忽略该名字，也不得因此回退成全量 |

## 4. 粒度契约

过滤按 **Agent 各自计算**。同一进程内两个声明不同的 Agent，其可用工具集合必须互不影响。

> 反面案例：把过滤结果缓存在全局变量里，第二个 Agent 会拿到第一个的工具集。
> 这类缺陷在单 Agent 场景下测不出来，因此必须有"两个 Agent 交替组装"的用例。

## 5. 与外部工具的关系

授权集合里可以包含外部服务提供的工具名（因为外部工具与内置工具在注册表中同形态）。
过滤逻辑**不区分来源**。

外部服务本身由 Agent 配置中的另一处字段按名字引用，未声明或为空 ⇒ 不限制
（与工具授权的空值语义保持一致）。

## 6. Required Verification

| # | 要求 | 验证方式 |
|---|---|---|
| 1 | 声明 3 个工具 → 暴露恰好 3 个 | 单测：断言集合**相等**（不是"包含"） |
| 2 | 两个声明不同的 Agent 交替组装，各自与自己的声明一致 | 单测：同一实例连续两次组装，断言互不污染 |
| 3 | 声明不存在的工具名 → 有可诊断提示，且**不**回退成全量 | 单测：断言提示内容 + 断言结果不为全量 |
| 4 | 声明缺失 / 为空 → 不限制 | 单测：断言等于注册表全集 |
| 5 | 过滤不区分工具来源（内置与外部工具同样受控） | 单测：注册表混入外部工具后重跑上述断言 |
