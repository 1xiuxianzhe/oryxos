# Contract: 外部工具服务接入

**Feature**: `005-tool-system`

## 1. 中立性

本契约描述的是"接入一档**外部工具服务**"，不是"接入某一家厂商"。
除传输方式与连接参数外，本契约的任何部分**不得**出现某个具体服务或协议实现特有的词汇。
自查：新增一种传输方式时，是否需要改调用方？答案必须是不需要。

## 2. 声明结构（工作区）

连接信息的唯一真相来源是工作区声明文件，形如：

```yaml
servers:
  # 方式一：本地子进程
  - name: weather
    transport: stdio
    command: npx
    args: ["-y", "@acme/weather-mcp"]
    env:
      ACME_API_KEY: ${ACME_API_KEY}     # 凭证一律用环境变量占位

  # 方式二：远程服务
  - name: ops
    transport: sse
    url: ${OPS_MCP_URL}
```

| 字段 | 必填性 | 说明 |
|---|---|---|
| `name` | 必填 | 服务标识；用于告警定位与 Agent 引用 |
| `transport` | 必填 | `stdio` / `sse`；取值非法时报错并跳过该条 |
| `command` / `args` / `env` | `stdio` 下 `command` 必填 | 本地子进程的启动方式 |
| `url` | `sse` 下必填 | 远程服务地址 |

**Agent 侧引用**：Agent 配置中的外部服务字段按 `name` 引用；未声明或为空 ⇒ 不限制。

## 3. 启动期流程契约

```text
文件缺失或 servers 为空  ──► 外部工具数 = 0，正常启动
逐条处理：
  transport / 必填项非法   ──► 告警一条，跳过该条，继续下一条
  建立连接失败（未启动 / 拒绝 / 超时） ──► 告警一条，跳过该服务，继续下一个
  连接成功 ──► 取回工具列表
        └─ 逐个包装为统一形态工具 ──► 注册（重名则拒绝并告警）
```

**硬约束**：

- 任一服务失败**不得**阻断启动（外部依赖的可用性 ≠ 自身的可用性）；
- 任一服务失败**不得**影响其它服务与内置工具的注册；
- 每个失败必须产生**一条可定位的告警**（含服务名与失败类别）。

## 4. 调用期契约

| 项 | 约定 |
|---|---|
| 参数转发 | 入参映射**原样**传给外部服务，不做改名、不补默认值 |
| 成功返回 | 返回内容拼接为文本，包装成统一成功结果 |
| 外部服务报告执行失败 | 包装成统一失败结果，**可重试** |
| 网络异常 / 超时 | 包装成统一失败结果，**可重试** |
| 服务中途失联 | 同上；**不得**导致进程崩溃或后续调用全部失败 |

## 5. 生命周期

应用停止时关闭已建立的连接，避免遗留悬挂的外部子进程。

## 6. 已知边界（避免误读）

| 项 | 本特性状态 |
|---|---|
| 本地子进程 / 远程两种连接方式 | ✅ 支持 |
| 服务在**运行期**新增或消失 | ❌ 不检测；连接与工具列表在启动时确定一次 |
| **连接失败的耗时** | ⚠️ 连接是**串行**的，每个失败的服务都要等满握手超时（默认 30 秒）。N 个失败服务会拖慢启动 N×30 秒。超时取 30 秒而非更短是实测决定：经包管理器转发的命令（`npx -y <包>`）首次运行需下载包，实测冷启动 21 秒、预热后 1.3 秒 |
| **失败原因的可诊断性** | ⚠️ 捕获到的异常几乎总是"握手超时"，**不是真实原因**。命令无法启动会被底层丢到后台线程打成 ERROR（`Failed to start process with command`）。因此失败告警会附带排查提示，指明去日志里搜这句话 |
| 工具列表变更通知 | ❌ 不消费 |
| 采样 / 根目录 / 提示词等协议高级能力 | ❌ 不使用，只用到"列出工具 + 调用工具" |
| 外部工具的域名白名单 | ❌ 不由本特性约束（交由外部服务自身）；但调用仍经统一执行链路与审计 |

## 7. Required Verification

| # | 要求 | 验证方式 |
|---|---|---|
| 1 | 声明文件缺失 → 正常启动、外部工具数为 0 | 单测 |
| 2 | 正常服务的工具全部被包装注册，形态与内置工具一致 | 单测：替身客户端返回工具列表 |
| 3 | 某服务连接失败 → 启动不失败、只告警、该服务工具不出现 | 单测：替身客户端抛连接异常 |
| 4 | 正常与失联服务同时存在 → 正常的可用、内置工具全可用 | 单测：两个替身，一好一坏 |
| 5 | 调用时参数**原样**转发 | 单测：断言替身收到的参数与传入一致 |
| 6 | 调用失败（含服务报告失败 / 网络异常）→ 统一失败结果且**可重试** | 单测：覆盖两种失败来源 |
| 7 | 外部工具与内置工具撞名 → 内置胜出，告警可见 | 单测 |
| 8 | `transport` 取值非法 / 必填项缺失 → 跳过该条并告警，不阻断启动 | 单测 |
| 9 | 应用停止时连接被关闭 | 单测：断言替身客户端收到关闭调用 |
| 10 | 外部工具调用写入审计 | 单测：替身审计器断言调用 |
