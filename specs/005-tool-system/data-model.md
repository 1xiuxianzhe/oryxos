# Phase 1 Data Model: Tool 体系

**Feature**: `005-tool-system` | **Date**: 2026-10-10

本特性**不新增数据库表、不修改既有表结构**（宪法「SQLite 表结构手动维护」）。
下表的"持久化"列标出各实体的落点：内存 / 配置文件 / 既有审计表。

## 1. 实体总览

| 实体 | 持久化 | 本特性动作 |
|---|---|---|
| 工具（Tool） | 内存 | 不改抽象；新增 6 个内置工具的**注册** |
| 工具注册表（Tool Registry） | 内存 | 改：补重名拒绝与存在性查询 |
| 工具执行结果（Tool Result） | 内存 | 不改 |
| 白名单策略（Sandbox Policy） | 配置文件 | **新增**：配置绑定 + 校验器装配 |
| 工具授权声明（Tool Grant） | 配置文件（Agent 配置） | **新增**：读取语义 + 过滤生效 |
| 外部服务声明（External Tool Server） | 配置文件（工作区） | **新增**：声明模型 + 读取组件 |
| 外部工具适配（External Tool Adapter） | 内存 | **新增**：外部工具 → 统一抽象 |
| 工具调用审计（Tool Invocation Audit） | SQLite（既有表） | 不改结构；保证新工具同样写入 |

## 2. 工具（Tool）

统一抽象，**对来源无感知**——内置、外部服务的工具在注册表里形态完全一致。

| 属性 | 类型 | 约束 |
|---|---|---|
| name | 字符串 | 全局唯一；模型据此点名 |
| description | 字符串 | 非空；给模型看 |
| inputSchema | 字符串 | 非空；JSON 文本形式的参数说明 |
| execute(input) | 行为 | 入参为字段名到值的映射；返回执行结果 |

**不变式**：任何注册进注册表的工具，四个成员都必须齐备且前三者非空（由契约测试自动兜住）。

**来源与命名**：

- 内置工具：`read_file`、`write_file`、`list_dir`、`shell`、`http_get`、`http_post`、`notify`（既有）
- 外部服务工具：沿用外部服务报出的名字，**不加前缀不改名**（plan D-06）

## 3. 工具注册表（Tool Registry）

进程内唯一真相来源。

| 行为 | 变更 |
|---|---|
| 注册工具 | **改**：名字已存在时拒绝并告警（先注册者胜出） |
| 按名取用 | 不变 |
| 全量列举 | 不变 |
| 存在性判断 | **新增**（清单入口与测试都需要，既有实现无此能力） |

**不变式**：注册表内容 = 工具清单两个入口返回的内容（同一来源，无缓存副本）。

## 4. 白名单策略（Sandbox Policy）

| 配置项 | 含义 | 备注 |
|---|---|---|
| 允许的路径清单 | 这些目录下的路径允许文件操作 | 前缀匹配，按解析后的真实路径判定 |
| 允许的命令清单 | 仅允许这些命令 | 取命令首个词精确匹配 |
| 允许的域名清单 | 仅允许这些主机的 HTTP 请求 | 支持通配 |

**不变式**：

- **任一清单为空 ⇒ 该维度一律拒绝**（fail-closed，A-005）；
- 校验**严格早于**副作用；拒绝时不发生读写、不启动进程、不发请求；
- 拒绝结果标记为**不可重试**；
- 配置格式非法（如非法通配、空字符串条目）⇒ 启动阶段报出可定位错误，不留到首次调用。

## 5. 工具授权声明（Tool Grant）

位于 Agent 配置中，声明该 Agent 允许使用哪些工具。

| 属性 | 类型 | 语义 |
|---|---|---|
| 工具名 | 字符串 | 必须是注册表中存在的名字；不存在时给出可诊断提示 |
| （兼容字段）描述 / 参数 | — | 当前**不参与**过滤，保留为后续扩展点 |

**语义规则**：

| 声明状态 | 该 Agent 可用工具 |
|---|---|
| 未声明，或声明为空 | **不限制**（注册表全部）— A-004，已确认 |
| 声明了 N 个名字 | **恰好**这 N 个（不多不少）；若某个名字在注册表中不存在，给出提示 |

**粒度**：按 Agent 各自计算，不跨 Agent 复用（FR-006）。

## 6. 外部服务声明（External Tool Server）

工作区声明文件中的一条记录，描述"怎么连上这个外部服务"。

| 属性 | 类型 | 适用连接方式 | 约束 |
|---|---|---|---|
| name | 字符串 | 两者 | 必填；用于告警定位与 Agent 引用 |
| transport | 枚举 | 两者 | 必填；本地子进程 / 远程 |
| command | 字符串 | 本地子进程 | 必填（该方式下） |
| args | 字符串列表 | 本地子进程 | 可选 |
| env | 字符串到字符串的映射 | 本地子进程 | 可选；值支持环境变量占位 |
| url | 字符串 | 远程 | 必填（该方式下）；支持环境变量占位 |

**Agent 侧引用**：Agent 配置中的外部服务字段语义为"该 Agent 引用哪些服务"（按 name）。
未声明或为空 ⇒ 不限制（与工具授权的空值语义保持一致）。

**可变现的默认值**（无可配置项时）：声明文件缺失或列表为空 ⇒ 外部工具数为零，应用正常启动。

## 7. 外部工具适配（External Tool Adapter）

把一个外部工具包装成与内置工具**完全同形态**的工具，从而注册进同一注册表。

| 统一抽象成员 | 来源 |
|---|---|
| name / description | 外部服务报出的对应字段 |
| inputSchema | 外部服务报出的结构化 schema **序列化为 JSON 文本** |
| execute(input) | 入参映射**原样**转发；返回内容拼接为文本、失败包装为可重试的失败结果 |

**不变式**：使用方（含 Agent）无法也不应区分工具来源。

## 8. 连接生命周期

```text
启动
  └─ 读取工作区声明文件
       ├─ 文件缺失 / 为空 ──► 外部工具数 = 0，正常启动
       └─ 逐条建立连接
            ├─ 成功 ──► 取回工具列表 ──► 逐个包装 ──► 注册（重名则拒绝并告警）
            └─ 失败 ──► 告警一条，跳过该服务，**不影响其余服务与内置工具**
```

**关闭**：应用停止时关闭已建立的连接，避免悬挂的外部子进程。

## 9. 与既有审计的关系

工具调用审计（SQLite 既有表）**结构不变**。本特性只保证：

- 新注册的内置工具经既有执行器链路，自动被审计覆盖；
- 外部工具同样经该链路（plan D-11），因此**不绕过**审计。

## 10. 配置清单（本特性新增）

| 位置 | 新增内容 |
|---|---|
| `application.yaml` | 白名单策略的三个清单（允许的路径 / 命令 / 域名/） |
| 工作区声明文件 | 外部服务声明列表（连接方式 + 连接信息） |
| Agent 配置 | 无新增字段；启用既有的工具授权声明与外部服务引用 |

> 配置文件中的凭证一律使用环境变量占位，不出现明文（沿用既有解析能力）。
