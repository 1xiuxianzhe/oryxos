## Notes

- **本规格最大的特点是"抽象层已完成、只缺接线"**：工具接口、执行结果、注册表、执行器、
  前置校验与审计钩子都已真实可用，内置工具类也有真实实现；缺的是**注册装配、校验器装配与配置来源、
  按 Agent 授权、对外接入、清单真实化**这五件事。因此规格刻意不重复描述已完成的抽象，
  只描述"要补的缺口对应的可观测行为"。
- **一处不可拆分的约束（A-003）**：内置工具强依赖非空的白名单校验器，缺失即构造失败。
  这决定了"工具可用"与"白名单生效"**必须一起交付**，不能拆成两个独立增量——
  这也是把白名单拦截写进 US1 验收场景（第 7~11 条）而不是单开一个故事的原因。
- **两个可反转决策点**，已显式记录代价、等待使用方确认：
  - **A-004**：Agent 未声明工具清单时视为"不限制"（与现行为兼容）还是"无工具"（治理更严）。
    当前取前者。
  - **A-009 / A-010**：外部工具服务的声明结构与实现底座（复用已声明但从未使用的 SDK，
    还是自实现协议转发）。当前留到 plan 阶段定稿。
- **一处平台假设（A-007）**：命令工具固定走 Windows 命令解释器，与源文档说的 `bash` 不一致。
  属既有独立缺口，本特性不改动，但在规格中显式标注，避免被误读为跨平台可用。
- 校验项全部通过，可进入 `/speckit.plan`。
