# Requirements Checklist: Web Service 与第一版管理平台

**Feature**: `009-web-admin` | **Date**: 2026-10-21

## 规格质量

- [x] 定位说清"门面"含义：业务系统接入的唯一通道，不是第二个引擎
- [x] 边界声明包含"不做什么"（认证/流式/限流/写操作/agents 增删改）
- [x] 与既有实现的 9 处冲突逐条收敛（C-1 ~ C-9），特别是"桩数据"与"500 泄漏"
- [x] 端点数量口径差异显式登记（文档 10 → 实际 13），每个多出的端点都有页面需求支撑
- [x] 用户故事均可独立验证，且验证方式不依赖真实模型
- [x] 功能需求（FR-001 ~ FR-020）可逐条对应代码或测试
- [x] 成功标准可度量（可达端点 13/13、硬编码业务数据 0、泄漏 0、写控件 0、外部依赖 0）

## 安全与边界

- [x] 500 不泄漏内部消息（现有实现泄漏，本轮修复）
- [x] 任何响应不含 api-key、绝对路径、白名单内容
- [x] 沙箱页只给条数（无认证阶段的信息最小化）
- [x] 前端用 `textContent` 渲染模型/文件内容（避免 XSS）
- [x] 认证缺失被明确标注为"上线前必须补"

## 架构一致性

- [x] Controller 薄：只校验 + 委托 + 包装（宪法 II / III）
- [x] 记忆经 `MemoryService` 门面读取（宪法 V，新增 `snapshot()`）
- [x] 审计链路不变：所有调用走 `AgentService`，invoke 用 `channel=invoke` 归类（宪法 VI）
- [x] 不新增模块、不新增第三方依赖、前端零 CDN
- [x] 表结构零变更（约束 5）

## 可验证性

- [x] 切片测试覆盖参数校验、委托次数、错误码、错误结构
- [x] 冒烟测试覆盖真实装配、静态资源、端点可达（`*Test` 命名确保进入 `mvn test`）
- [x] 前端验收有逐页核对表与断网检查项
- [x] 错误语义给出可直接照抄的 curl
