# Requirements Checklist: Sandbox 统一抽象与白名单校验

**Feature**: `007-sandbox` | **Date**: 2026-10-20

## 规格质量

- [x] 背景与定位写清了"为什么现在做"（005 留下的三方法校验器 vs 23/24 节要求的中立抽象）
- [x] 边界声明包含"不做什么"（不写容器/microVM、不用 SecurityManager、不改审计链路）
- [x] 与既有实现的 7 处冲突逐条给出收敛结论（C-1 ~ C-7），不留"实现时再说"
- [x] 用户故事按优先级排列，每个故事有独立可执行的验证方式
- [x] 每个验收场景都是 Given/When/Then 且可观察（失败消息、副作用探针、调用顺序）
- [x] 功能需求（FR-001 ~ FR-017）可逐条对应到代码位置或测试
- [x] 成功标准可度量（100% 拦截、0 副作用、公开入口数为 1、BUILD SUCCESS）
- [x] 假设（A-001 ~ A-008）显式记录代价，包含配置形状、删类、notify 位置、大小写

## 安全边界

- [x] 明确了"第一档只是劝阻，不是关押"，未包装成强隔离
- [x] 空清单默认拒绝（fail-closed），不放行
- [x] 覆盖经典绕过：`..` 穿越、符号链接、域名形似、命令前导空白/大小写
- [x] 拒绝不得改写为成功、不得吞掉
- [x] 审计沿用既有链路，不新增旁路

## 架构一致性

- [x] 全部落在 `oryxos-tool`，不新增模块（宪法 IV）
- [x] 不使用 Spring AI 自动 tool 执行 / `@Tool` 注解注册（宪法 III）
- [x] 不使用 `SecurityManager`（宪法约束 4）
- [x] 不引入核心阶段禁用能力（并行 tool、SSE、认证、向量检索）
- [x] 审计表写入不受影响（宪法 VI）

## 可验证性

- [x] 每个 Required Verification 项都有落点测试类（contracts 第 5 节）
- [x] 接线回归全部使用"副作用为零"探针，而非只断言异常
- [x] 附人工集成验证步骤（真实白名单 + 审计落库检查）
- [x] 接口中立性检验写成可复核的推演，而非口头结论
