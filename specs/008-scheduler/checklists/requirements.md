# Requirements Checklist: 定时任务模块（AgentScheduler）

**Feature**: `008-scheduler` | **Date**: 2026-10-20

## 规格质量

- [x] 背景与定位写清了"第三种触发源"的含义（同一 `AgentService` 入口，不改 ReAct/Tool/Provider）
- [x] 边界声明包含"不做什么"（工作流编排、分布式协调、任务管理 API、重试、告警）
- [x] 与既有实现的 8 处冲突逐条收敛（C-1 ~ C-8），含 `schedules` 死字段的处理方式
- [x] 用户故事按优先级排列，每个故事都有不依赖真实时间的验证方式
- [x] 验收场景可观察（注册参数、调用次数、锁是否释放、日志是否可定位）
- [x] 功能需求（FR-001 ~ FR-017）可逐条对应代码位置或测试
- [x] 成功标准可度量（注册率 100%、重叠跳过 100%、启动失败 0 次、时区差 8 小时）
- [x] 假设（A-001 ~ A-009）显式记录代价（id 必填、锁键含 profile、跳过非法配置、复用会话）

## 边界与安全

- [x] 未引入分布式锁 / 选主 / 租约（核心阶段单实例）
- [x] 未引入重试与告警
- [x] 未新增审计结构（复用 `agent_runs` 及下游明细）
- [x] 定时触发经 `AgentService`，因此不绕过 Sandbox 与工具审计
- [x] 失败不静默：ERROR 日志 + 既有审计留下的失败记录

## 架构一致性

- [x] 不新增 Maven 模块（宪法 I）
- [x] 不碰 ReAct 循环（宪法 II）
- [x] 不引 Spring AI 自动执行（宪法 III）
- [x] 不触碰 Tool / Memory 模块（宪法 IV / V）
- [x] 表结构零变更（约束 5）

## 可验证性

- [x] 注册阶段用 mock `TaskScheduler` 抓参数，不真等时间
- [x] 触发阶段直接调 `runOnce`，覆盖防重叠 / 失败隔离 / 会话身份
- [x] 时区用固定时钟断言"下一次执行时刻"，而非断言字符串
- [x] "锁已释放"用二次触发断言（只断言不抛异常抓不到漏 unlock）
- [x] 附真实到点验证步骤（含审计表检查点）
